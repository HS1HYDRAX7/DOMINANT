3. LOADER (loader.lua)
===================================================================

3.1 Tela de loading
- Estilo Ophyn, tema Dark (fundo preto, detalhes brancos, nada verde).
- Sequência: quadrado com logo (80 px) -> cresce até 460x260 -> spinner -> status.
- Cada etapa começa quando a anterior termina (Tween.Completed:Wait()).
- Ao terminar, fade-out e destruição da ScreenGui.
- A ScreenGui do loading precisa ficar ACIMA da Vind. A Vind usa
  DisplayOrder = 9999 na sua ScreenGui principal. O loading deve usar
  DisplayOrder maior que 9999 (ex.: 10000) enquanto estiver visível.
- Enquanto a tela de key do Ophyn estiver aberta, o loading fica oculto
  (gui.Enabled = false) e reaparece depois que a key for aceita.

3.2 Idioma do loading
- Lê Dominant/session_<GameId>.json (o mesmo arquivo do Settings).
- Se não existir ou não tiver idioma, usa inglês (en).

3.3 Robustez
- Watchdog: se uma etapa ('modules', 'game', 'window') passar de 25 s sem
  mudar, mostra o erro com motivo e botão "Tentar de novo".
- Erros do pcall mostram a causa na tela (máximo 90 caracteres).
- Botão de tentar de novo reinicia a sequência sem recriar a tela.
- Antes de iniciar, descarrega a instância anterior (env.DominantInstance).

3.4 Logo
- Baixa assets/logo.png do repositório para Dominant/Assets/logo.png (uma vez)
  e usa getcustomasset. Se não houver função de arquivo, usa o asset padrão.
- O Ophyn recebe a logo como rbxassetid (ver 4.1). Nunca passe caminho
  local (getcustomasset) para o Ophyn: o PreloadAsync dele trava.

===================================================================
4. CORREÇÕES OBRIGATÓRIAS (já descobertas)
===================================================================

4.1 Ophyn: o campo de key só aparece depois que PreloadAsync termina
    (iconsPreloaded = true). Esse preload inclui o Logo. Por isso o Logo
    do Ophyn tem que ser um rbxassetid (ex.: rbxassetid://116590139091461)
    e nunca um caminho de arquivo local.

4.2 Tema da key: config.KeyTheme = "Dark" (branco). Não usar "Plant-Dark".

4.3 Vind:
    - Window:SetBackground(options) aceita Image e Transparency. Não aceita
      escala (Fit/Stretch): a imagem é sempre Crop.
    - Não existe Window:ClearBackground. Para limpar use
      Window:SetBackground({ Image = "" }).
    - Window:SetBackgroundTransparency(n) existe.
    - Confirm(opts) usa Title, Text, ConfirmText, CancelText, Danger, Window e
      Callback(confirmed).
    - Tab:AddKeybind(opts) usa Text, Description, Icon, Default e Callback(key, kind).
      kind é "bind" (ao definir) ou "press" (ao pressionar).
    - Tab:AddChangelogEntry(opts) usa Version, Date e Changes (lista de tabelas
      com os campos Type e Text).
    - Tab:AddCard(opts) usa UserId, Title, Description.
    - Tab:AddSubTab(opts) cria subabas; opts tem Name e Icon.
    - Tab:AddParagraph(opts) usa Title, Icon, Text e devolve objeto com .Instance.
    Confira qualquer função nova em full_luau.txt antes de usar.

4.4 Sincronização: use Tween.Completed:Wait() para encadear etapas, nunca
    soma de task.wait().

4.5 Não existe "Proton" na documentação pública que consegui acessar.
    O chat usa um servidor relay (ver seção 7).

7. CHAT (Chat tab)
===================================================================

O Photon Chat é em tempo real (WebSocket). Não há API HTTP para clientes.
Use um servidor relay próprio, alimentado por webhooks do Photon:

  POST {api}/rooms                     -> { "code": "..." }
  POST {api}/messages                  body { code, name, message }
  GET  {api}/messages?code=&after=N    -> { "messages": [{ name, message }] }

Campo "Chat server" (URL). Sala por código. Mensagens com Enter.
Não invente o protocolo do Photon.
